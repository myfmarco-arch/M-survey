# 研究方案

产品和数字均为虚构。

## 研究简报（ResearchBrief）

| 项目 | 内容 |
|---|---|
| 业务决策 | 下季度优先改进自动分类的哪些问题 |
| 研究问题 | RQ1 知道并使用自动分类的比例；RQ2 使用者的总体和分项评价；RQ3 使用者遇到的问题、频率和影响；RQ4 知道但未使用的原因 |
| 评价对象与阶段 | 已上线两个月的自动分类功能；受访者为近 30 天自报使用者（实际体验）和未使用者（认知与阻碍） |
| 目标人群 | 近 30 天在账小满有记账行为的成年用户 |
| 排除条件 | 未满 18 岁；记账类产品从业者；近 30 天没有记账 |
| 比较关系 | 使用者与未使用者分开分析；不做版本或时间比较 |
| 约束 | 约 6 分钟；App 内消息邀约；匿名，不关联账号，不收集联系方式 |
| 假设 | 甄别通过率约 97%（活跃用户中未成年人和从业者占比较低），没有历史依据；自报使用率按 30% 规划（埋点触发率为 40%，自动运行的功能常有用户不知道自己用过）。两项都在回收前 200 份后复核 |

## 方法方案（MethodPlan）

```text
业务决策：下季度自动分类改进优先级
→ 研究问题：RQ1–RQ4
→ 首选方法：标准结构化问卷（认知、使用、体验评价、问题发生率和频率、首要问题）
→ 推荐理由：决策需要的是“哪些问题最常见、影响最大”，属于描述和痛点定位（方法目录 D02、D03、D04），不需要相对效用或需求分类
→ 成立前提：问题选项来自客服记录和埋点中的高频修改场景（已满足，由团队提供）；评价只由自报使用者回答（Q2 对所有人提问，不以知道功能名称为前提，避免漏掉不知道名称的使用者）
→ 不推荐的方法：KANO（回答的是需求类型，不是问题优先级）；MaxDiff（候选项是已发生的问题而不是待选需求，发生率和频率更直接）
→ 必需测量：认知、30 天使用、总体满意度、分项表现、问题发生、频率、首要问题、未使用原因
→ 主要指标和分析：各问题在使用者中的发生率及 95% 置信区间；频率分布；首要问题占比；分项表现与总体满意度的相关（只作关联参考）
→ 样本和分析影响：使用者为主要分析单元，样本按使用者规划
→ 结论边界：见下文
```

## 样本方案（SamplePlan）

| 项目 | 内容 |
|---|---|
| 目标总体与来源 | 近 30 天有记账行为的成年用户；从活跃用户名单中随机抽取，App 内消息邀约 |
| 主要分析 | 自报使用者中各问题的发生率（比例估计） |
| 最小分析单元 | 自报使用者（Q2 选 1 或 2） |
| 输入参数 | 95% 置信水平（z = 1.96）；允许误差 ±5 个百分点；预期比例未知，取保守值 p = 0.5 |
| 计算方法 | n0 = z² × p × (1-p) ÷ e² = 1.96² × 0.25 ÷ 0.05² ≈ 384.2，向上取整为 385。总体规模远大于样本，不做有限总体修正 |
| 计算所得有效样本数 | 自报使用者 385 份 |
| 项目建议最低有效样本数 | 项目未另行给出 |
| 总完成样本 | 385 ÷ 30%（自报使用率，规划假设）≈ 1,284 份；该样本下全体比例的误差约 ±2.7 个百分点。自报使用率为 25%–40% 时，需要约 963–1,540 份 |
| 损耗假设 | 甄别通过率 97%（假设）；开始后完成率 85%（历史）；邀约后开始率 8%（历史） |
| 建议邀约量 | 385 ÷ 30% ÷ 97% ÷ 85% ÷ 8% ≈ 19,500 人。开始率为 6%–10% 时约需 15,600–26,000 人；自报使用率和开始率同时取范围两端时约需 11,700–31,200 人 |
| 执行规则 | 先发 19,500 人；回收 300 份后用实际自报使用率和开始率重算，不足时追加邀约 |
| 配额 | 不设配额。用 D1 使用时长与用户库结构比较，偏差明显时事后加权，并报告设计效应 |

计算假设随机抽取的受访者全部作答。实际只有约 8% 的人开始作答，自选择可能使结果偏向更活跃或更愿意反馈的用户。误差范围只反映抽样误差，不包含无应答偏差。

回收后比较自报使用率与埋点触发率（40%），差异较大时在报告中说明，并考虑功能认知不足本身就是需要改进的问题。

## 结论边界

- 可以说：在作答的近 30 天活跃用户中，各问题的发生率、频率和首要问题占比。
- 可以说：分项表现与总体满意度的关联强弱，作为改进方向的参考。
- 不能说：某个问题“导致”满意度下降或用户流失。横截面问卷只能说明关联。
- 不能说：满意度或问题发生率代表全部活跃用户的真实情况。结论限定在作答者范围内，并说明自选择风险。
- 不能用未使用者的回答评价自动分类的实际体验。

# 方法选择服务

本服务从 ResearchBrief 选择主要方法和必要的辅助测量。不根据单个关键词直接选方法。

## 决策顺序

1. 明确结果要支持的业务决策。
2. 明确评价对象和体验阶段。
3. 确认用户是否实际接触或使用评价对象。
4. 判断需要绝对评价、相对排序、属性分类、组合权衡还是因果比较。
5. 排除前提不成立的方法。
6. 选择一个主要方法。只增加支持解释和行动所必需的辅助测量。
7. 将每个指标连接到变量、计分和拟议分析。

## 核心区分

| 需要的结果 | 优先考虑 | 不要替代为 |
|---|---|---|
| 需求类型及满意反应非对称性 | KANO | 相对优先级排序 |
| 多个项目之间的相对取舍 | MaxDiff | 绝对满意度或需求类型 |
| 属性水平组合的权衡 | 选择型联合分析 | 单属性重要性评分 |
| 交易或任务后的整体评价 | CSAT 或任务级测量 | 真实留存或购买行为 |
| 两个条件是否产生差异 | 随机化调查实验 | 非随机组间相关 |

详细方法从 [方法索引](../modules/methods/index.md) 加载；可用方法列表以 `product.yaml` 的 `modules.methods` 和已启用 overlay 新增的方法为准。未在列表中的方法可以使用，但需要独立模块时必须符合 [模块合同](../contracts/module-contract.md)。

## 类型边界

方法选择前先标记用户提到的名称属于哪一层。不要根据单个名称直接生成问卷。

| 层级 | 判断问题 | 例子 |
|---|---|---|
| 研究项目/测量设计 | 研究范围、样本和时间点如何组织？ | BHT、U&A、追踪研究、概念测试 |
| 方法 | 研究问题如何转换成任务和主要输出？ | KANO、MaxDiff/BWS、CBC/DCE、PSM、Gabor-Granger、随机化调查实验 |
| 题型/任务 | 受访者具体做什么？ | 评分、排序、Best-Worst、选择任务、价格判断 |
| 模型/估计 | 如何把回答估计成参数或预测？ | 多项 Logit、Mixed Logit、HB、潜类别、回归、CFA/SEM |
| 指标/量表 | 追踪或测量什么构念？ | NPS、CSAT、SUS、品牌认知率、考虑率 |
| 工具/平台 | 用什么软件执行或分析？ | Qualtrics、Sawtooth、Conjointly、R、Python、SPSS |

MaxDiff 在方法层记录为 Best-Worst Scaling / MaxDiff，在题型层记录为“每个任务选择一个最重要和一个最不重要”。BHT 在方法库中记录为品牌健康度追踪项目设计，不记录为单一题型或单一模型。价格测试按目标路由：价格区间用 PSM，明确价格点反应用 Gabor-Granger，价格与功能一起权衡用含价格属性的 CBC/DCE。

## 输出

MethodPlan 应简要说明：

```text
业务决策
→ 研究问题
→ 首选方法
→ 推荐理由
→ 成立前提及满足状态
→ 不推荐的方法及原因（只列用户提到或容易误用的方法）
→ 必需测量和辅助测量
→ 主要指标和拟议分析
→ 样本和分析影响
→ 结论边界
```

本服务是方法决策顺序和 MethodPlan 格式的唯一定义处。[方法目录](../modules/methods/catalog.md) 和方法模块只提供方法知识，不重复定义决策顺序。

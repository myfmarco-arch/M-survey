# 任务路由服务

本服务将用户请求转换为工作模式和必需能力。先利用用户材料中的已知信息，再判断是否需要询问。

## 路由结果

| 模式 | 输入 | 主要产物 |
|---|---|---|
| `create` | 业务需求、研究问题或新问卷请求 | ResearchBrief、MethodPlan、SamplePlan（需要时）、QuestionnaireSpec |
| `revise` | 现有问卷和修改目标 | 修订后 QuestionnaireSpec、变更说明 |
| `audit` | 现有问卷和审核范围 | ValidationResult |
| `consult` | 方法、样本或测量问题 | MethodPlan 或 SamplePlan |

SamplePlan 只在用户要求样本量、配额或样本框架，或问卷需要据此设计甄别和配额时产出。

## 基本流程

```text
解析产品配置和 overlay
→ 判断适用范围
→ 形成或更新 ResearchBrief
→ 判断缺口是否会改变核心设计
→ 选择所需服务和方法
→ 产生或修改研究产物
→ 运行验证
→ 调用适配器交付
```

## 澄清规则

当且仅当缺失信息会改变以下任一内容时，先询问用户：

- 主要方法。
- 样本或分析单元。
- 问卷核心模块。
- 法律、伦理或隐私处理。
- 新旧数据的可合并性。

非关键缺口可以使用简短假设，但假设必须记录在 `ResearchBrief.assumptions`。

## 加载原则

- 方法咨询不加载完整问卷模板。
- 不涉及样本建议时，不主动扩展样本规划说明。
- 只有需要标准题组时才读取题库。
- 只有需要结构参考时才读取案例，默认一份，最多两份。
- 只有用户要求 Codebook 或 SPSS 配置时才加载对应适配器。

## 不在范围内

普通报名表、纯定性访谈大纲、问卷平台编程与设备测试、回收数据清洗和已有数据统计分析不进入本流程。可以说明边界并建议后续能力，不伪装成问卷设计继续处理。

## 规则

| rule_id | 检查 | 默认严重程度 |
|---|---|---|
| `routing.out-of-scope` | 超出范围的请求说明边界，不伪装成问卷设计继续处理，不编造分析结果 | `error` |
| `routing.consult` | 方法咨询说明首选方法、前提、替代方案和结论边界，不强制生成问卷 | `warning` |
| `routing.clarify` | 只询问会改变方法、样本、核心结构、合规处理或数据可合并性的缺口；提问数量不超过当前产品配置 | `warning` |
| `routing.assumption-recorded` | 非关键缺口使用的假设记录在 `ResearchBrief.assumptions`，不与已知事实混同 | `warning` |

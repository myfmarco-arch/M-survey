# 问卷需求澄清问题集合

用途：在推荐定量方法和生成问卷前，识别研究目的、评价对象、目标人群、比较关系和执行约束。

本文件是知识模块，只定义“需要知道什么”。每轮提问数量、提问语气和交付结构由当前产品配置决定（官方产品见 [工作流](../../products/survey-zh-default/workflow.md)）。问题 ID、触发条件和回答字段以 [clarification-questions.csv](clarification-questions.csv) 为准；修改时两者同步。

分两个文件读取：

| 文件 | 内容 | 什么时候读 |
|---|---|---|
| 本文件 | 使用规则、首轮 6 个核心问题、方法路由和停止条件 | 每次需要澄清时 |
| [条件追问与执行约束](clarification-probes.md) | 15 个条件追问、5 个执行约束问题、对话示例 | 核心回答触发条件主题时 |

答案字段对应研究产物，见 [研究产物合同](../../contracts/artifacts.md)。

## 1. 使用规则

这组问题是问卷 skill 的需求澄清层。它先判断研究要支持什么决策，再判断适用的方法。用户不需要先知道 NPS、KANO、SUS 或联合分析。

1. 首轮提问数量不超过当前产品配置的上限。
2. 根据核心回答触发条件问题。
3. 已知信息不重复询问。
4. 方法的必要前提未满足时继续追问。
5. 信息足够时停止追问，把未确认内容标为假设。
6. 不把意向、满意度或推荐意愿直接当作真实行为。
7. 每个方法推荐都说明适用原因、成立前提、限制和辅助测量。
8. 阅读问题库是为了检查信息是否齐全，不等于必须向用户提问。

机器可读版本见 [clarification-questions.csv](clarification-questions.csv)。

## 2. 首轮核心问题（信息清单）

以下 6 个核心问题是信息检查清单，不是必须全部发出的问题。已知信息不问；实际提问数量受当前产品配置的首轮上限约束。可以合并成一段对话，但不要同时发出冗长的完整问卷。

| ID | 建议提问 | 回答字段 | 直接影响 |
|---|---|---|---|
| C01 | 这次调研要支持哪个业务决策？结果出来后，谁会根据结果做什么决定？ | decision_owner；decision；decision_deadline | 决定研究问题、指标和交付形式。 |
| C02 | 您要评价什么对象？受访者已经接触它了吗？处于认知、考虑、首次使用、最近一次交易还是长期使用阶段？ | object_type；object_name；experience_stage；last_experience_time | 区分交易、任务、系统、关系、功能、概念、品牌和价格测量。 |
| C03 | 您最想得到哪一类答案：描述现状、找原因、排优先级、比较方案、预测行为、解释采用，还是评估效果？ | research_question_type；primary_output | 路由到描述题、驱动分析、MaxDiff、KANO、联合分析、实验或预测模型。 |
| C04 | 您希望代表哪一类人？哪些人必须排除？请说明地区、身份、使用资格、使用频率和其他筛选条件。 | target_population；inclusion；exclusion；market_scope | 决定筛选题、抽样框、配额和结果外推边界。 |
| C05 | 您需要比较哪些人群、版本、概念、价格、时间点或干预条件？这些对象能否随机分配或保持同一测量口径？ | comparison_units；comparison_type；randomization_possible；time_points | 决定交叉表、分层、随机化实验、前后测或联合分析。 |
| C06 | 受访者从哪里来？预计样本量、配额、问卷时长、预算、平台和截止时间是什么？ | source；sample_size；quotas；length；budget；platform；deadline | 判断样本是否支持分组、模型和实验；参数充分时生成配额建议。 |

核心问题的判断顺序：业务决策 → 评价对象和体验阶段 → 研究问题类型 → 目标人群 → 比较关系 → 执行约束。

如果 C01 不能回答，先追问业务决策。  
如果 C02 不能回答，先确认受访者是否实际体验过对象。  
如果 C03 不能回答，要求用户在“描述、解释、排序、比较、预测、评估”中选择最接近的一类。  
如果 C04 不能回答，不输出样本代表性结论。  
如果 C05 不能回答，不默认存在因果比较。  
如果 C06 不能回答，可以先给方法方向，但不输出精确样本量、每格样本或邀约量。需要样本建议时读取 [样本规划](../../services/sample-planning.md)。

## 3. 方法路由和停止条件

| 用户要回答的问题 | 优先考虑 |
|---|---|
| 现状是什么、发生了多少、哪些人不同 | 标准结构化问卷、发生率和分层描述 |
| 一个品类如何被使用、用户有哪些需求和态度 | U&A（Usage & Attitude）研究 |
| 为什么发生、哪些因素关联结果 | 原因题、属性题、驱动分析；必要时加入行为数据 |
| 多个需求中相对更重要的是什么 | MaxDiff |
| 有无某功能带来的满意反应是否不同 | KANO |
| 功能、价格和服务如何取舍 | 选择型联合分析 |
| 一个任务是否容易 | SEQ 加任务行为 |
| 一个系统总体是否好用 | SUS 或 UMUX-LITE |
| 一次体验是否满意 | 交易型 CSAT |
| 一段关系是否稳定、是否会续用 | 忠诚意向加实际行为窗口 |
| 不同版本是否产生差异 | 随机化调查实验 |
| 不同时间点是否发生变化 | 面板、重复横截面或带对照前后测 |
| 品牌健康指标如何跨波次变化 | BHT（Brand Health Tracking）加固定核心 KPI 和轮换模块 |
| 哪些人形成稳定且可行动的群体 | 潜类别分析或经验证的分群规则 |

推荐方法前至少检查：评价对象明确；受访者有足够体验或信息；研究问题与方法输出一致；题目或任务可理解；随机化、平衡设计或重复测量可执行；样本量和配额支持目标分析；正式题组、语言版本和计分方式可核验。

任一关键前提不成立时，先输出缺口并追加问题，不直接输出“推荐方法”。

以下信息足够时可以停止追问：主要业务决策、评价对象和体验阶段、主要研究问题、目标人群和排除条件、比较单位、样本和问卷约束已经确定，或缺口已经明确。

交接格式：

业务决策 → 研究问题 → 评价对象和体验阶段 → 目标人群与排除条件 → 比较关系 → 首选方法 → 方法前提 → 辅助测量 → 样本与配额影响 → 未确认信息和假设。

随后按当前产品的工作流和模板生成交付物。

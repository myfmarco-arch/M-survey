# 官方中文问卷工作流

本文件是 `survey-zh-default` 的默认工作流。它是产品选择，不是所有兼容产品必须复制的唯一流程。

## 设计顺序

```text
业务决策
→ 研究问题
→ 主要指标
→ 分析对象和比较关系
→ 研究方法
→ 样本与配额
→ 问卷模块
→ 题目和选项
→ 显示与跳转说明
→ 编码配置
→ 验证
```

每道题服务于研究问题、样本控制或问卷内容逻辑。不能说明用途的题目应删除。

## 交互默认值

- 先从用户材料提取已知信息，不重复询问。
- 第一轮最多提出 6 个编号问题。一个编号问题可以包含紧密相关的子问（例如“评价什么对象？受访者用过吗？”），但不把无关问题合并凑数。这是官方产品默认值，可由 overlay 覆盖。
- 信息充分时直接继续。非关键缺口使用显式假设。
- 复杂或高风险方法先交付简短研究简报，再进入完整问卷。
- 简单且信息充分的任务一次完成。

## 常用测量链路

| 任务 | 默认链路 |
|---|---|
| 体验诊断 | 使用资格 → 整体评价 → 一级方向 → 场景 → 功能 → 具体问题 → 改进建议 |
| 卖点复盘 | 购买前认知 → 购买吸引 → TOP1 → 实际体验 → 满意度 → 低分原因 |
| 购买决策 | 购买背景 → 对比范围 → 信息渠道 → 关注因素 → 相对取舍 → 关键因素深挖 |
| 新功能需求 | 当前行为 → 未满足问题 → 使用场景 → 功能需求 → 需求类型或优先级 → 使用阻碍 |
| 概念测试 | 使用资格 → 随机展示 → 单方案评价 → 方案比较 → 高低分原因 → 最佳方案 |
| 用户招募 | 基本条件 → 设备或行为资格 → 深度经验 → 表达能力 → 时间意愿 → 联系方式 |

## 问卷负担

- 只向用户展示与其经历有关的模块。
- 使用显示逻辑、答案引用、循环和 TOP 因素追问控制长度。
- 长列表随机普通选项，特殊选项按语义固定位置。
- 长矩阵拆分、随机模块或只追问关键项目。
- 开放题只用于补充遗漏、解释原因、收集案例或筛选表达能力。

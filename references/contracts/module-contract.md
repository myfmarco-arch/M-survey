# 模块合同

`m-survey-contract-v1`。当前 revision 见 [contracts/manifest.json](../../contracts/manifest.json)，声明兼容时写成 `m-survey-contract-v1@<revision>`。

模块是一份可被产品选择、替换或复制修改的能力文件。M-survey 第一版使用源码级组合，不要求动态插件加载。组合和覆盖规则见 [组合与覆盖合同](overlay-contract.md)。

## 模块类型

| 类型 | 责任 | 例子 |
|---|---|---|
| `service` | 处理多种任务共用的能力 | 任务路由、方法选择、样本规划、质量验证 |
| `method` | 实现一种具体研究方法或研究项目设计；模块正文必须标明概念层级 | KANO、MaxDiff、联合分析、品牌健康度追踪 |
| `knowledge` | 提供题库、澄清问题、领域概念或方法来源 | 澄清问题、行业术语表 |
| `adapter` | 将研究产物转换为交付格式 | Markdown、Codebook、SPSS |
| `profile` | 定义工作流、写作、格式和编码默认值 | `survey-zh-default` |
| `overlay` | 替换或扩展产品默认值，新增方法、知识、适配器和验证 | 团队撰写规范、平台编码 |

### 分层约束

- `knowledge` 和 `method` 不定义产品默认值，例如提问轮数、交付结构、标题格式或具体编码。需要时引用当前产品配置。
- `adapter` 不定义题目语义，只表达 QuestionnaireSpec。
- `profile` 不改变合同和验证服务。
- 下层文件不得引用 overlay 中的具体文件。

## 方法模块必需章节

方法模块必须按以下顺序使用十个二级标题（`##`），标题文字保持一致，便于机器检查：

| 标题 | 内容 |
|---|---|
| `## 解决的问题` | 可以支持哪类决策 |
| `## 适用条件` | 什么情况可以使用 |
| `## 不适用条件` | 什么情况应该拒绝或更换方法；写明替代方法 |
| `## 必需输入` | 使用 [研究产物合同](artifacts.md) 中的字段名称 |
| `## 设计和样本要求` | 必要参数、任务设计和数量影响 |
| `## 产生的输出` | 明确写入哪种研究产物 |
| `## 允许的结论` | 证据支持的结论范围 |
| `## 不允许的结论` | 明确禁止的推断 |
| `## 验证规则` | 可观察的通过和失败条件；对应 `method.<id>.*` 规则 |
| `## 来源与许可` | 区分原始方法、官方题组、工作译文和项目模板 |

方法文件开头可以增加一行元数据：

```markdown
<!-- module: method; id: kano; contract: m-survey-contract-v1 -->
```

## 输入与输出

- 模块只读取完成当前任务必需的产物。
- 模块不静默重写用户事实、历史编码或其他模块的输出。
- 模块发现缺少必需输入时，返回验证结果；不编造数值或事实。
- 模块可以提供默认值。默认值必须标明为默认值，且可被用户或 overlay 覆盖。

## 替换和覆盖

使用者复制需要修改的官方模块，将副本放入自己的 overlay，在 `overlay.yaml` 中声明 `replace` 或 `extend`，再在 `product.yaml` 中启用该 overlay。完整格式见 [组合与覆盖合同](overlay-contract.md)。

overlay 不得在不报告的情况下改变已有题目语义、数据合同、量表真实性或证据状态。

## 最小兼容条件

一个模块在以下条件全部满足时可声明与 `m-survey-contract-v1` 兼容：

- 必需输入可以从研究产物中获取。
- 输出不破坏产物字段语义。
- 缺少信息和冲突使用统一验证结果报告。
- 没有未声明的必需依赖。
- 方法模块包含上表的十个章节。
- 通过与该模块有关的兼容性评测，且至少有一个正向评测和一个边界或反向评测。
